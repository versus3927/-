# Исправление распознавания матчей

Изменения в `bot.py`:

- Ответ кнопки «Получить игроков» привязывается к номеру матча и, когда Discord предоставляет данные, к исходному сообщению.
- Для карточек «на проверку» анализируется только исходный игровой скриншот, а не изображения из ответа кнопки.
- Добавлен отдельный строгий режим распознавания табло STANDOFF 2.
- Исправлен новый формат карточки, где в «Команда A/B» есть только строки `#ID ник`, а окно «Получить игроков» возвращает нулевые K/A/D.
- Для такого формата кнопка «Получить игроков» не нажимается: ID и ники берутся прямо из Команды A/B в карточке, а счёт, стороны CT/T и K/A/D — из исходного скриншота.
- Счёт копируется слева направо без прибавления завершившегося/следующего раунда.
- Учтён столбец «Деньги» перед У/П/С у команды атаки.
- ID берутся из окна игроков, но K/A/D и счёт — из исходного скриншота.
- Команды и игроки сопоставляются по никам; при неоднозначности регистрация отменяется.
- Бот не отправляет `=g`, если уверенность распознавания ниже 0.90.

## Рекомендуемые переменные Railway для первого теста

```env
PROCESS_CONCURRENCY=1
GEMINI_MAX_RETRIES=1
```

После нескольких успешных матчей можно увеличить значения. Не загружайте `.env` с реальными токенами в GitHub.

- Добавлена команда `забыть <номер>` для удаления одной игры из памяти через Discord.
- Дубликаты одной игры больше не мешают обработке: регистрируется одна карточка, а после ответа `Готово` все карточки с тем же номером матча удаляются из канала.
- Если матч уже есть в сохранённой статистике регистраций, его повторные карточки удаляются без повторной команды `=g`.
- Если обработка единственной активной копии завершилась ошибкой, оставшиеся дубли не считаются навсегда просмотренными и повторяются при следующем `старт`.
- Табло с четырьмя игроками на одной стороне теперь принимается: отсутствующий пятый игрок определяется по карточке и регистрируется как `0 0 13`.
- Разделены два формата: готовая карточка `внесён` сохраняет свои K/A/D, а карточка `на проверку` получает K/A/D со скриншота.
- Исправлено распознавание русских заголовков `К/А/С` в готовых карточках — они больше не попадают ошибочно в режим пустых ID/ников.
- `0 0 13` назначается только игроку без совпадающего ника на скриншоте (игрок отсутствует или на табло указан другой ник). Статистика остальных игроков не заменяется.
- Поддержаны две отсутствующие строки на одной стороне: табло 5×3 теперь регистрируется, а оба отсутствующих игрока получают `0 0 13`.
- После успешной регистрации автоматически удаляется сообщение регистрационного бота `Готово — Матч #... закрыт`. Ошибки `Не вышло` остаются в канале.
- Добавлена команда `удалить рег соо`: она просматривает полную историю всех обычных и приоритетных каналов регистрации и удаляет старые сообщения формата `Готово — Матч #... закрыт со счётом...`.
- Минимум финального результата снижен до четырёх надёжно сопоставленных игроков суммарно. Остальные игроки карточки получают `0 0 13`; требуется хотя бы одно совпадение с каждой стороны.
- Команда `бот ты тут?` показывает готовность, активность авторега, пользователя из `MY_ACCOUNT_ID`, текущую Discord-сессию, статистику и конфигурацию без секретов, а также прикладывает HTML-отчёт.
- Ограничение команд по `MY_ACCOUNT_ID` удалено: `старт`, `енд`, `стата`, `забыть`, очистка сообщений и проверка статуса доступны всем пользователям.
- Пересланные карточки вне активных каналов регистрации распознаются как тестовые и получают в ответ только готовое сообщение `=g`.
- Тестовые пересылки не сохраняются в статистике, не ожидают `Готово` и не удаляются.
- Алгоритмы распознавания карточек, скриншотов, ников, счёта и K/A/D не изменены.
- После успешной регистрации в лог отправляется исходная карточка игры: сначала настоящей пересылкой, а при недоступности пересылки — резервной копией с текстом и изображениями.
- Исходная карточка копируется в лог до автоматического удаления из канала регистрации.
- Добавлена автосистема варнов для игроков, которым из-за отсутствия совпадения назначено `0 0 13`.
- В канал `WARN_CHANNEL_ID` отправляются тег игрока, причина (`неправильный ник` или `нет на скриншоте`) и исходная карточка со скриншотом.
- Игроки с ролью «Про Лига»/`Pro League` и пользователи из `PRO_LEAGUE_USER_IDS` исключаются из автоварнов.
- Роль вида `🔴 Pro League` распознаётся даже с дополнительными эмодзи или значками.
- Список исключений `PRO_LEAGUE_USER_IDS` перенесён из Railway Variables непосредственно в `bot.py`.
- Каждый фактически выданный автоварн дополнительно записывается в `LOG_CHANNEL_ID` с игроком, причиной, матчем и счётом.
- Формат варна приведён к образцу: отдельное сообщение на игрока, тег в первой строке, причина и номер матча во второй строке, исходный скриншот в том же сообщении.
- Неправильный ник отображается как `Додж статистики - #MATCH`, отсутствие игрока — как `Отсутствие на финальном скриншоте - #MATCH`.
- В лог отправляется точная копия каждого выданного варна вместе со скриншотом.
- Исправлен пропуск варна для видимой строки `0/0/0`: при преобразовании в регистрационные `0 0 13` игрок теперь получает причину `Додж статистики` и записывается в канал варнов и логи.
- Если `WARN_CHANNEL_ID` не настроен, причина пропуска теперь явно пишется в Railway Deploy Logs.
- Добавлена финальная проверка прямо перед отправкой `=g`: каждый игрок с итоговыми `0 0 13` получает метку для автоварна независимо от того, каким путём карточка была распознана.
- Исправлен матч формата #2908, где несколько `0 0 13` пришли из другого обработчика карточки и поэтому не попадали в систему варнов.
- Исправлены варны без настоящего тега: если карточка содержит только ник (`ezio`, `Робот`), бот ищет совпадающий профиль среди участников общих серверов и использует `<@Discord ID>`.
- Сопоставление учитывает серверные ники с клановым префиксом, например `ezio` совпадает с профилем `MCRW | ezio`.
- После нахождения профиля роль `🔴 Pro League` проверяется в `member.roles`; таким игрокам варн не отправляется.
- Исправлен случай, когда Discord snapshot не заполняет `message.mentions`: реальные `<@Discord ID>` теперь извлекаются из сырых секций `Команда A/B` и сопоставляются по порядку игроков.
- Варн `Hatefull` и аналогичные больше не должны показывать ник кодом — при наличии упоминания в карточке используется настоящий Discord-тег.

- Формулировки варнов приведены к правилам: отсутствие игрока на финальном скриншоте — «Отсутствие на финальном скриншоте», а несовпадение ника при всех 10 игроках — «Несоответствие игрового никнейма».
- Сервисные упоминания вида `@Система` больше не попадают в сопоставление: берутся только строки состава с номером регистрации.
- Каждый игрок обрабатывается отдельно, поэтому сбой одного варна больше не отменяет остальные (пропавший второй варн).
- В логи добавлены строки «кандидатов на варн» и «отправлено варнов X из Y».

Версия исправления: `v35-warning-reasons-and-per-player-delivery-2026-09-10`.

## v51 — теги во всех автоварнах

- Исправлены варны без тега (ник кодом, например `csn`) при «Несоответствии игрового никнейма». Раньше Discord-профиль искался по нику со скриншота, а у такого игрока он по определению не совпадает с ником в Discord.
- Discord ID игрока теперь в первую очередь берётся из самой карточки: регистрационный номер `#ID` сопоставляется с упоминанием `<@игрок>`, в серверном нике которого стоит этот номер (`#124 | OLD | Shkiper`). Это работает и для пересланных карточек, где snapshot отдаёт пользователей без серверных ников.
- Строки состава только с упоминанием (`❓ <@id>`) больше не пропускаются при сопоставлении по порядку. Порядок используется только при полном составе из 5 строк и если номер в нике упоминания совпадает с ID игрока.
- Для всех игроков сохраняется ник из карточки (`card_nickname`): поиск идёт сначала по нему, затем по нику со скриншота.
- Поиск участника на сервере дополнительно выполняется по `#ID`, потому что серверные ники начинаются с регистрационного номера.
- После упоминания учитывается только явный `#ID`, поэтому `<@id> — 12/3/4` больше не может быть ошибочно принят за игрока #12.
- Если тег всё же не найден, в Railway Deploy Logs пишется строка «Discord-профиль игрока #ID (ник) не найден, варн будет без тега».
- Распознавание карточек, скриншотов, счёта и K/A/D не изменялось.

Версия исправления: `v51-warning-tags-for-every-player-2026-09-13`.

## v52 — удаление карточки и «Готово» после регистрации

- Исправлено: после регистрации карточка матча и сообщение «Готово — Матч #… закрыт» оставались в канале, а удалялась только команда `=g`. Бот не узнавал ответ «Готово», считал регистрацию неудачной (тайм-аут) и сохранял карточку.
- Ответ регистрационного бота теперь ищется во всём тексте сообщения: содержимое, заголовок, описание, поля, **автор и футер embed**, текстовые компоненты. Успехом считается «Готово» или «Матч #N закрыт со счётом».
- Ожидание ответа включается **до** отправки `=g`, поэтому быстрый ответ больше не теряется.
- Учитывается ответ, который сначала отправлен, а потом изменён на «Готово».
- Если событие от Discord не пришло, бот каждые 4 секунды и в конце ожидания перечитывает канал после своей команды.
- Номер матча сравнивается точно: ответ по `#34801` больше не подходит для матча `#3480`.
- Варны отправляются в фоне после скачивания скриншота, поэтому карточка удаляется сразу, а не после долгого поиска Discord-профилей.
- Если у аккаунта нет права удалить «Готово» или карточку, в `LOG_CHANNEL_ID` приходит уведомление «нужно право „Управлять сообщениями“».
- При тайм-ауте в Deploy Logs пишутся тексты сообщений, пришедших после команды, чтобы был виден формат ответа.
- Команда `удалить рег соо` использует тот же расширенный поиск текста.

Версия исправления: `v52-registration-cleanup-after-confirmation-2026-09-13`.

## v53 — «Готово» удаляется всегда

- Исправлено: после регистрации карточка и `=g` удалялись, а «Готово — Матч #… закрыт» оставалось. Турнирный бот после закрытия матча редактирует карточку. Если изменённая карточка приходила раньше ответа, v52 принимал её за «Готово» и удалял карточку вместо ответа.
- Ответом на `=g` считаются только сообщения, созданные после отправки команды. Карточки «Результат матча #…» ответом не считаются.
- Цикл ожидания реагирует на первое пришедшее событие сразу, а не раз в секунду.
- После удаления карточки бот перечитывает канал и удаляет все оставшиеся «Готово» по этому матчу, затем повторяет проверку через 15 секунд.
- Страховка: любое новое или изменённое сообщение «Готово — Матч #N закрыт» в каналах регистрации удаляется, если матч N уже есть в истории регистраций этого бота. «Готово» по играм, зарегистрированным людьми, не трогается.
- В Deploy Logs пишется каждое удалённое «Готово»: «Матч #N: удалено «Готово» (сообщение …)».

Версия исправления: `v53-delete-every-ready-reply-2026-09-13`.

## v54 — причины пропуска игр в логах и команда `удалить рег соо`

- Игры, которые бот пропускал молча, теперь попадают в `LOG_CHANNEL_ID` сообщением «❌ Ошибка регистрации игры #N» с причиной:
  - скриншот распознан как открытый TAB во время игры, а не финальный экран;
  - регистрационный бот не ответил «Готово» (тайм-аут или «Не вышло») — с отправленной командой `=g`, ответом бота и сообщениями, пришедшими после команды.
- Раньше обе причины писались только в Railway Deploy Logs, поэтому снаружи игра выглядела «просто не зарегистрированной».
- `удалить рег соо` находила 0 сообщений: «Готово» искалось только в начале строки сразу после обычного ✅. Теперь «Готово — Матч #N закрыт со счётом X:Y» распознаётся с жирным шрифтом (`**Готово**`, `**#N**`), эмодзи ✅️, кастомными эмодзи и в новом формате сообщений Discord (история читается в сыром виде).
- Если команда ничего не удалила, но нашла похожее сообщение, она показывает его текст прямо в Discord.
- Та же проверка используется при автоудалении «Готово» после регистрации.
- Исправлены 7 строк с битыми символами `��`, которые были в исходном архиве, в том числе в тексте запроса к модели распознавания (`Результат матча #`).

Версия исправления: `v54-visible-skips-and-cleanup-command-2026-09-13`.

## v56 — карточки с открытым TAB удаляются

- Если на скриншоте карточки открыт TAB во время игры, а не финальный экран, игра не регистрируется, а карточка удаляется из канала регистрации.
- Перед удалением в `LOG_CHANNEL_ID` отправляются «❌ Ошибка регистрации игры #N» с причиной и блоком «ЧТО МОДЕЛЬ ПРОЧИТАЛА НА ТАБЛО», затем копия самой карточки. Если модель ошиблась, игру можно зарегистрировать вручную по этой копии.
- Удаляется только сама карточка с TAB; другие карточки того же матча не трогаются.
- Тестовые пересылки карточек вне каналов регистрации по-прежнему никогда не удаляются.
- Если у аккаунта нет права удалить карточку, в лог-канал приходит уведомление.

Версия исправления: `v56-delete-live-tab-cards-2026-09-13`.

## v57 — игры не падают из-за сбоя ИИ, картинки или кнопки

- Исправлено «Необработанное исключение в process_upload» у обоих форматов карточек. Разбор форматов был исправен, падал внешний вызов, и одна его ошибка останавливала всю игру.
- ИИ: если назначенная модель или ключ не отвечает (кончился баланс или лимит, неверное имя модели, ошибка сети, битый JSON), бот по очереди пробует все остальные пары «модель + ключ» из `GEMINI_MODELS` и `GEMINI_API_KEY_*`. Если не сработала ни одна, в логе перечислен ответ каждой пары.
- Картинки: каждая ссылка карточки скачивается отдельно; при ошибке пробуется зеркало `media.discordapp.net`; битая миниатюра больше не мешает, если сам скриншот скачался.
- «Получить игроков»: ошибка Discord при нажатии кнопки больше не роняет обработку. В лог пишется «Не удалось открыть/прочитать «Получить игроков»» с причиной: кнопка не нажалась с ошибкой или турнирный бот не прислал список вовремя.
- «❌ Ошибка регистрации игры» при любом необработанном исключении теперь содержит текст ошибки и место в коде («ОШИБКА: …», «ГДЕ: …»), а не только составы.
- Проверено сквозным тестом `process_upload`: старая карточка «на проверку» с `#ID ник`, новая карточка с упоминаниями и K/A/C, новая карточка с игроками без `#ID` в нике (ID из «Получить игроков») — все три регистрируются правильной командой `=g`.

Версия исправления: `v57-ai-fallback-and-error-details-2026-09-14`.
